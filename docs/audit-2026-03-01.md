### Beat Schedule Conflict:
`celery_app.py:44-49` — beat only schedules `run_discovery_all` (all clients every 2h). `run_discovery_tick` (single-client rotation) exists but **is not scheduled**. This means discovery always fans out to every client simultaneously rather than using the rate-smoothing tick design.

**Remediation:**
1. Wire billing page to create a Stripe Checkout Session via `/api/checkout/create`.
2. Wire analytics page to `GET /api/clients/{id}/analytics`.
3. Build whitelist CRUD: add/remove endpoint on `PATCH /api/clients/{id}` for `whitelist_domains`.
4. Wire admin pages to `GET /api/admin/metrics` and `GET /api/admin/dlq`.
5. Replace `run_discovery_all` in beat schedule with `run_discovery_tick` at 900s interval.

## B. Error Handling & Resilience
**Status: NEEDS WORK**

### Bare Excepts Swallowing Errors:

| Location | Line | Issue |
|----------|------|-------|
| `api/assets.py` | 125-127 | `except Exception: pass` — silently swallows vectorize task dispatch failure. Upload succeeds, asset is never vectorized. No log, no user feedback. |
| `api/takedown.py` | 80-82 | `except Exception: pass` — silently swallows queue dispatch. Takedown row is created in DB but never executed. |
| `workers/takedown.py` | 282, 296 | `except Exception: continue` in `_fill_first` and `_click_first` — intentional UX resilience but should log failures |
| `workers/takedown.py` | 652, 689 | `except Exception: pass` — silently skips checkbox checking and LOA attach failures |

### DLQ:
**Implemented correctly.** `_insert_dlq()` in takedown worker fires after 5th retry failure. `GET /api/admin/dlq` reads from the `dead_letter_queue` or `dlq` table.

### Retry Mechanism:
- Takedown: `60 * (2 ** next_retry)` — exponential backoff. **Correct.**
- OpenAI/HuggingFace embedding: `_post_with_retry` with backoff. **Correct.**
- SerpApi: **No retry.** Single call with no retry on 429/500.
- Supabase calls: **No retry** anywhere.

### Failure Mode Analysis:

| Failure | Current Behavior | Gap |
|---------|-----------------|-----|
| Supabase down | Workers raise `RuntimeError`, API returns 500. | No user-visible degraded mode. |
| Redis crash | Discovery falls back to time-based cursor. Workers stop and restart via systemd. | Queued tasks lost if Redis has no persistence. |
| OpenAI 429 | `_post_with_retry` retries 3x. | No circuit breaker. |
| SerpApi 429/down | No retry. Entire task fails. | Wastes retry slot. |
